# 开发日志模板

> 用法：复制本文件为 `YYYY-MM.md`（如 `2026-09.md`），按月累积。
> **每条只写一行**，格式：`- [类型] 一句话摘要 → [链接](相对本文件的路径)`
> 类型固定七种：`沟通` / `变更` / `打样` / `问题` / `测试` / `决策` / `发布`
> 这里是索引，不是正文——正文放各自的归档目录，本文件只引用。
> 详细规则见根目录 `README.md` 第三节。

---

## YYYY-MM-DD

- [沟通] 例：客户确认灯组件线束不指定、开关指定 → [原件](../../00_input/沟通记录/20260924_客户A_线束开关确认.pdf)
- [变更] 例：欠压保护阈值 2.8V → 2.6V，客户 9/23 邮件同意 → [ECN-003](../变更记录_ECN/ECN-003_欠压阈值调整.md)
- [打样] 例：V1.1 板回样 5pcs，功能正常，空载电流偏高 → [打样记录](../../02_hardware/打样记录/V1.1_20260920/)
- [问题] 例：-10℃ 下堵转保护误触发，已定位到 ADC 采样时序 → [问题-005](../问题追踪/问题-005_低温堵转误触发.md)
- [测试] 例：效率测试完成，额定点 82.3%，MAP 图见报告 → [测试报告](../../04_report/测试报告/)
- [决策] 例：放弃无感 FOC，改用霍尔六步换相，理由是 BOM 成本 → [系统方案设计](../../01_docs/系统方案设计/)
- [发布] 例：发布 V1.0 固件给产线 → [固件版本索引](../../05_output/固件_bin/版本索引.md)

## 为什么值得花这个时间

三个月后回看，你会记得结论，但记不住「当时为什么这么决定」「客户哪天点头的」「哪一版板子出的这个问题」。
这份日志是唯一能把这些串起来的东西，而且成本只有每件事一行。
